# PRD：Git 面板 V2

面向 DeepSeek Harness Web 人类开发者的 Git 面板：在工具箱中与资源管理器平级，对当前 Session 绑定 Workspace 所发现的 Git 仓库根查看工作区变更、暂存、丢弃、提交，并在面板内做差异预览。

领域词汇见 `[CONTEXT.md](../../CONTEXT.md)`。架构决策见 `[docs/adr/0003-git-panel-host-rpc.md](../adr/0003-git-panel-host-rpc.md)`、`[docs/adr/0004-git-panel-client-plugin.md](../adr/0004-git-panel-client-plugin.md)`；壳层先例见 `[docs/adr/0002-file-editor-details-tab.md](../adr/0002-file-editor-details-tab.md)`。品牌视觉 Token 与原语见 `[docs/design/DESIGN.md](../design/DESIGN.md)`；本 PRD 只引用，不重写色板或字号表。资源管理器行为以 `[docs/prd/file-editor-v1.md](./file-editor-v1.md)` 为准，本 PRD 不重写编辑界面。

## 问题陈述

人类开发者在 dsh Web 里与 Agent 并排改代码时，只能在文件树上看只读 Git 状态标记，无法在同一工具箱里查看已落盘的工作区变更、按文件或差异块暂存、写提交说明并提交。要完成一次提交，必须离开 Web 去用外部 Git GUI 或终端，和对话、显式保存脱节。未保存的编辑缓冲若被 Git 操作碰到磁盘，还可能出现「丢弃成功后又被保存写回」。绑定 Workspace 常常是大仓库里的子目录：用户需要看见整个仓库的变更并提交，但不能因此打开绑定范围外的文件。不是仓库与本机没有 git 若混成同一种「没徽章」，用户分不清该初始化还是该安装 git。

## 解决方案

在现有工具箱分段 Tab 增加与资源管理器、工具详情平级的「Git」段。选中后展示 Git 面板：只读当前分支、更改与暂存的更改两段列表、提交说明与提交、以及面板内的差异预览。列表与预览只认磁盘工作区，不含未显式保存的编辑缓冲；显式保存成功后与文件树 Git 状态标记一起刷新。可整文件或按差异块暂存 / 取消暂存；丢弃只作用于未暂存内容且须确认。暂存区为空或说明为空时不可提交。目标路径存在 dirty 编辑器标签页时，Git 操作守卫禁止丢弃与暂存（含按块）以及包含该路径的提交，不自动保存；取消暂存不受限。仓库根从绑定 Workspace 向上发现；范围外路径可预览与 Git 操作，不可打开文件编辑器。向上找不到仓库且 Git 可用时可初始化仓库（打在绑定 Workspace 根）；Git 不可用时说明原因且不提供初始化。切走 Git Tab 只隐藏视图，不取消暂存。

## 用户故事

仅 Web 端。序号在全文唯一递增。

US-1：作为 Web 开发者，我想在工具箱打开「Git」分段 Tab，以便在对话旁查看并操作当前仓库的工作区变更。

US-2：作为 Web 开发者，我想在「资源管理器 | Git | 工具详情」三段之间切换且同时只显示一段，以便 Git 与资源管理器、工具详情平级共存。

US-3：作为 Web 开发者，当我切走 Git Tab 时，我想只隐藏视图、不取消暂存、不清空提交说明草稿，以便稍后再回来继续提交。

US-4：作为 Web 开发者，我想拖宽工具箱，以便给变更列表和差异预览更多水平空间。

US-5：作为 Web 开发者，我想让 Git 面板跟随当前选中 Session 的绑定 Workspace，并从该目录向上发现 Git 仓库根，以便列表与该 Session 的仓库一致。

US-6：作为 Web 开发者，当我切换 Session 时，我想 Git 面板改跟新仓库，且上一 Session 的提交说明草稿仍在、且草稿不走 Session 切换守卫，以便换会话不会弄丢说明、也不会被未提交说明拦住。

US-7：作为 Web 开发者，我想只读看到当前分支名（无分支时看到 Git 对空前 HEAD 的说明），以便知道提交会打在哪条线上。

US-8：作为 Web 开发者，当提交因缺少 `user.name` / `user.email` 或其它 Git 原因失败时，我想看到 Git 的失败原因，且面板不让我填身份、不用 Session 用户顶替，以便按本机 Git 配置修复。

US-9：作为 Web 开发者，我想在「更改」段看到已落盘但未暂存的工作区变更，以便挑选要暂存的文件。

US-10：作为 Web 开发者，我想在「暂存的更改」段看到已进入暂存区的工作区变更，以便确认即将提交的内容。

US-11：作为 Web 开发者，当同一路径只有部分差异块已暂存时，我想它同时出现在两段，以便继续按块处理剩余差异。

US-12：作为 Web 开发者，我不想在变更列表里看到被 Git 忽略的路径，以便列表与 `git status` 一致；文件树仍可全量可见。

US-13：作为 Web 开发者，当工作区干净（无更改也无暂存）时，我想看到明确空态，以便知道没有可提交的内容。

US-14：作为 Web 开发者，我想整文件暂存一条更改，以便把它移入暂存区。

US-15：作为 Web 开发者，我想整文件取消暂存，以便把它退回更改列表且不改磁盘。

US-16：作为 Web 开发者，我想丢弃一条未暂存的工作区变更并先确认：已跟踪修改恢复磁盘、未跟踪则从磁盘删除、已跟踪删除则把文件恢复到磁盘，以免误改磁盘。

US-17：作为 Web 开发者，我不想在「暂存的更改」段看到丢弃，以免把「取消暂存」和「丢掉已暂存内容」搞混。

US-18：作为 Web 开发者，我想填写非空提交说明后才能提交，以免做出没有说明的提交。

US-19：作为 Web 开发者，当暂存区为空时，我想提交按钮禁用，以免误把未暂存更改一起提交。

US-20：作为 Web 开发者，我想提交说明草稿按 Session 保存，切 Tab 或切 Session 都不清空，提交成功后才清空该 Session 草稿，以便写到一半的说明还在。

US-21：作为 Web 开发者，我想点提交只把当前暂存区做成一次新提交、打在当前 HEAD 上，不做 amend、不推送远程，以便提交含义单一。

US-22：作为 Web 开发者，我想单击一条工作区变更后在 Git 面板内看到差异预览，且不打开、不替换编辑器标签页，以便看 diff 与改文件分开。

US-23：作为 Web 开发者，对于已跟踪文本，我想看到行级差异，并按差异块暂存、取消暂存，以及对未暂存块按块丢弃（须确认），以便只提交或丢掉一部分改动。

US-24：作为 Web 开发者，对于未跟踪文本，我想预览整文件为新增，且只能整文件暂存或丢弃，以便新建文件不必假装成差异块。

US-25：作为 Web 开发者，对于二进制文件，我想看到「有差异」的说明且只能整文件操作，以免对无法按行 diff 的文件按块操作。

US-26：作为 Web 开发者，对于删除，若旧内容可当文本我想看到删除内容，且只能整文件暂存或丢弃（丢弃删除=恢复文件），以便处理删文件。

US-27：作为 Web 开发者，当变更路径在 Git 仓库根内、绑定 Workspace 之外时，我想仍能预览与 Git 操作，但不能在文件编辑器打开它，以便提交整仓同时守住编辑根。

US-28：作为 Web 开发者，当某路径存在 dirty 的编辑器标签页时，我想被禁止对该路径丢弃、整文件或按块暂存，以及禁止包含该路径的提交，以免丢弃后又被显式保存写回。

US-29：作为 Web 开发者，当路径 dirty 时我仍想取消暂存，因为取消暂存不改磁盘。

US-30：作为 Web 开发者，当 Git 操作守卫拦住我时，我想被提示先显式保存、丢弃该编辑缓冲或关闭该 Tab，且系统不自动保存。

US-31：作为 Web 开发者，当 Git 可用且向上找不到仓库根时，我想在 Git 面板初始化仓库（打在绑定 Workspace 根），以便开始用 Git；不发布到 GitHub。

US-32：作为 Web 开发者，当找不到 git 可执行文件时，我想看到 Git 不可用说明，且没有初始化按钮，也不把磁盘上已有的 `.git` 说成不是仓库。

US-33：作为 Web 开发者，仅当整条祖先链都没有仓库时才出现初始化，以免在已有仓库内部再 init 成嵌套仓库。

US-34：作为 Web 开发者，当存在合并冲突文件时，我想把它当作工作区变更来看 diff、按既有规则暂存或丢弃，并在文件编辑器（仅绑定范围内）编辑保存后再暂存；不要合并编辑器或 abort/continue。

US-35：作为 Web 开发者，我想在切到 Git Tab、Git 面板自身操作完成、显式保存成功、切换 Session 完成后按磁盘重读，以便列表与磁盘对齐。

US-36：作为 Web 开发者，当我一直停在 Git Tab 时，我不要求面板立刻跟上 Agent 或终端的改写，以免为实时监视付出 V2 范围外的成本。

US-37：作为 Web 开发者，当 Git 面板操作改变工作区后，我想文件树的 Git 状态标记也同步刷新，以便两边速览一致。

US-38：作为 Web 开发者，当我在资源管理器显式保存成功后，我想 Git 面板与徽章一起按磁盘刷新，以便刚保存的改动出现在更改列表。

US-39：作为 Web 开发者，我不想让未显式保存的编辑缓冲出现在变更列表或差异预览里，以便 Git 只认磁盘。

US-40：作为 Web 开发者，当列表刷新、暂存、提交较慢时，我想在 Git 面板内看到加载反馈，且不挡住整个 dsh Web。

US-41：作为 Web 开发者，当暂存、丢弃、提交或初始化失败时，我想在面板内看到错误说明（提交/初始化可重试），以便从 Git 失败中恢复。

US-42：作为 Web 开发者，我想 Git 面板跟随 Harness 的 light/dark，以便与对话区和资源管理器观感一致。

### 状态策略

加载中 / 空 / 错误 / 禁用 / 对话框是同一页的状态变体，不是独立 UI 页。变体写在各页 UI 设计描述末尾，或复用 `DESIGN.md` §5。禁止为变体单独出设计稿。禁止用全屏遮罩挡住整个 dsh Web。


| 状态  | 处理方式                                                                                                                                                                                                                        |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 加载中 | 复用 DESIGN §5 Loading。首次进入 / 刷新列表：内容区居中 24px spinner + 12px `label-secondary` 文案「加载中…」。单行暂存/取消暂存：该行右侧 16px spinner（`label-caption`）。提交中：提交按钮内 spinner，按钮禁用。Git 状态刷新：列表顶 2px 高 indeterminate 条（`semantic-info`），不遮罩整表。        |
| 空状态 | 复用 DESIGN §5 空状态（48px outline 图标 + 标题 14px `label-primary` + 说明 12px `label-secondary` + 可选主按钮 CTA，包在 overlay 卡片内）。四种互斥空态见 `git-panel` 变体段：**Git 不可用**、**不是 Git 仓库**（可初始化）、**干净工作区**、**未选中变更**（右侧预览空）。被忽略的路径不是空态：列表里本来就不出现。 |
| 错误  | 复用 DESIGN §5 输入错误态。空提交说明：多行框边框 `semantic-error`，说明「请填写提交说明」（提交仍禁用）。提交/暂存/丢弃/初始化失败：面板内 `semantic-error` 展示 Git 失败原因；提交与初始化另提供可点「重试」。Git 操作守卫：对话框说明须先显式保存、丢弃编辑缓冲或关闭该 Tab，不自动保存。                                               |
| 禁用  | 暂存区为空或提交说明为空：主按钮「提交」禁用。目标路径 dirty：该行暂存/丢弃图标禁用（取消暂存不禁用）；含该路径时「提交」禁用。Git 不可用：无「初始化仓库」。提交中、丢弃确认提交中：主按钮禁用。                                                                                                                      |
| 对话框 | 丢弃确认、Git 操作守卫：均为 `git-panel` 浮层变体，表面 `bg-layer-3`，复用 DESIGN §5 按钮（主 / 次 / 危险）。不是独立 page-id。无 Git 版外部变更对话框。                                                                                                                  |

## 实现决策

摘要 ADR-0003 / ADR-0004；定位词供下游 `/to-issues`、`/tdd` 逐字引用。

### Host Git RPC 契约

在现有 Host API 上扩展一组**有类型的** Git RPC，Client 只消费 RPC、不直接接触仓库。不提供任意 argv 的 `git` 通道；按块暂存的 patch 拼装与 `git apply` 等细节留在 Host。须能区分 **Git 不可用** 与 **不是 Git 仓库**（后者仅当 Git 可用且从绑定 Workspace 向上找不到仓库根）。建议操作与语义：发现仓库根与当前分支、读取更改与暂存的更改（不含被忽略路径；路径相对仓库根，可为绑定 Workspace 之外的绝对路径）、读取差异预览（已跟踪文本行级；未跟踪文本整文件新增；二进制仅声明有差异；删除在可当文本时给出旧内容）、整文件与按差异块的暂存 / 取消暂存、丢弃工作区变更（仅未暂存；已跟踪修改恢复为暂存区或 HEAD；未跟踪删除磁盘；已跟踪删除恢复文件）、提交（非空说明、非空暂存区、作者只取 Git 配置）、初始化仓库（仅打在绑定 Workspace 根）。V1 的 `gitStatus` 徽章语义保持：非仓库或 git 不可用时文件树仍返回空列表、不报错。

### ui-git

新建 Client 插件包承载 Git 面板：两段变更列表、提交说明、提交、差异预览、初始化与 Git 不可用空态、丢弃确认与 Git 操作守卫对话框。经槽位注入工具箱的 Git 段。不得 import `ui-file-editor` 的内部符号。提交说明草稿按 Session 保存在 Client store，不写入 Session 日志（人类 UI 状态，非模型可见输入）。切走 Git Tab 只卸载视图，不取消暂存、不清空草稿；提交成功后清空该 Session 草稿。

### 工具箱三段 Tab

`ui-conversation` 将工具箱 segmented Tab 扩为「资源管理器 | Git | 工具详情」，并声明 Git 槽位。ADR-0002「编辑界面进 details、不新开第四栏」仍然成立。同时只显示一段。切走 Git 不取消暂存。复用右栏拖宽与 concession。`ui-file-editor` 仍只承载资源管理器与只读 Git 状态标记；Git 面板操作成功后须让徽章与面板两边都能按磁盘刷新。

### dirty 路径会话集合

Git 操作守卫所需的 dirty 路径由 `ui-conversation` 提供会话级只读集合：`ui-file-editor` 写入，`ui-git` 只读。不把该集合放进 runtime 对象层。路径用绝对路径；Git 面板判断某工作区变更是否命中 dirty 集合。命中则禁止对该路径丢弃、整文件或按块暂存，以及禁止包含该路径的提交；取消暂存不受限。不自动保存。守卫以对话框提示先显式保存、丢弃该编辑缓冲或关闭该 Tab。

### 刷新与只认磁盘

列表与差异预览只认已落盘工作区，不含编辑缓冲。在切到 Git Tab、Git 面板自身操作完成、显式保存成功、切换 Session 完成后按磁盘重读。停在 Git Tab 期间不保证被 Agent 或终端改写后立刻刷新。不发明 Git 版外部变更对话框。

## 测试决策

只测外部行为，不测 Host 拼 patch 的内部字符串、diff 像素、主题 HEX、hook 调用次数。定位词与接缝一一对应。

### Host Git RPC 集成 seam

在现有 Host API / `gitStatus` 测试先例上断言新 Git RPC 的响应字段与失败码：更改与暂存的更改分段正确；忽略路径不出现；Git 不可用与不是仓库可区分；初始化只在无祖先仓库时打在绑定 Workspace 根；暂存 / 取消暂存 / 丢弃后磁盘与返回列表一致；按块操作只改变对应差异块；提交要求非空说明与非空暂存区，作者来自 Git 配置，失败返回 Git 原因；不暴露任意 argv。V1 `gitStatus` 在非仓库或 git 不可用时仍为空列表。不测 porcelain 解析器的内部分片。

### ui-git 组件 seam

用 Fake Host API 与注入的 dirty 路径集合驱动 `ui-git`，断言用户可见行为：两段列表与段级全部暂存 / 全部取消暂存；单击行只切换面板内差异预览、不打开编辑器标签页；空暂存或空说明时提交禁用；dirty 路径上暂存/丢弃禁用且提交禁用，取消暂存仍可；非仓库展示初始化 CTA，Git 不可用无该 CTA；切走 Tab 后暂存区与草稿仍在；提交成功清空草稿。不断言 className、内部 store 字段名或 patch 文本。

### Web browser snapshot seam

在现有 Web 浏览器快照车道（`details-segmented-tab`）增加组装场景：工具箱分段 Tab 可见「资源管理器 | Git | 工具详情」；选中 Git 后的默认态（干净仓库空态或非仓库空态，由夹具决定）。断言规范化 DOM/文案快照，不把差异预览像素或主题 HEX 写入期望。人类可见文案或 Tab 标签变更须更新该快照。

## 范围外

V2 不做下列事项（Not now）：

- 提交历史图、对 diff 做自动找问题（Agent Review）
- 合并编辑器、abort / continue、切换或创建或合并分支
- 发布到 GitHub、push、远程绑定、amend、Commit & Push、Smart Commit（空暂存区提交全部未暂存）
- 按行暂存（细于差异块）、强制跟踪被忽略路径（`add -f`）
- Git 版外部变更对话框；停在 Git Tab 期间对 Agent/终端改写的实时监视
- 面板内填写 `user.name` / `user.email`，或用 Session / 系统用户顶替作者
- 提交说明模板编辑器
- Terminal 面板、第四栏、把 Git 操作写成 Agent 工具或 Session 日志中的 bash
- 浏览器内 isomorphic-git、独立 Git HTTP 服务、任意 argv 的 `git` 通道
- 改 V1 文件树全量可见约定，或让文件编辑器打开绑定 Workspace 之外的路径



## 补充说明

依赖：V1 工具箱、资源管理器、Host `gitStatus` 徽章与显式保存已存在；Session 切换守卫仍只处理 dirty 编辑缓冲。Git 面板写操作走新的有类型 RPC，不能假设只读 `gitStatus` 足够。

风险：大仓库的 status / diff 可能慢；分层 Loading 是缓解而非消除。仓库根高于绑定 Workspace 时，列表可能含用户在文件树里看不见的路径——这是有意的整仓提交语义。停在 Git Tab 时列表可能短暂陈旧，刷新后以磁盘为准。

开放问题：无。文案、空态互斥与守卫规则以本 PRD 与 `CONTEXT.md` 为准；实现阶段若需增补差异预览的罕见二进制类型提示，先改本 PRD 再改代码。
