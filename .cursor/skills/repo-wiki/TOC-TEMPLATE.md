# Repo Wiki 目录模板

`/repo-wiki` 生成 Wiki 时必须遵循此目录结构。路径相对于 `docs/repo-wiki/`。

## 固定目录（8 类主题）

| 序号 | 文件 / 目录 | 主题 | 必须覆盖 |
|------|-------------|------|----------|
| 0 | `README.md` | 项目身份 | 一句话定位、技术栈摘要、入口文件源码锚点、本 Wiki 使用说明 |
| 1 | `01-execution-flow.md` | 主执行链路 | 从请求 / CLI / 事件到核心逻辑的端到端路径，每层带源码锚点 |
| 2 | `02-core-modules/index.md` | 模块总览 | 核心模块列表、职责摘要、模块间依赖关系图（可选） |
| 2 | `02-core-modules/{name}.md` | 各核心模块 | 每个核心 package / 目录一页；按代码实际结构拆分，不宜过多细碎页 |
| 3 | `03-cross-boundaries.md` | 跨端边界 | 前后端、服务间、monorepo packages 交界；API client、DTO、共享类型 |
| 4 | `04-data-state-flow.md` | 数据与状态流 | 持久化、缓存、状态机、事件传播 |
| 5 | `05-config-boundaries.md` | 配置边界 | env、配置文件、feature flag 生效点 |
| 6 | `06-extension-points.md` | 扩展点 | 插件 hook、策略模式 seam、可替换适配器 |
| 7 | `07-risk-points.md` | 风险点 | 高耦合、缺测试、与 ADR 不一致处、技术债 |

可选：`diagrams/*.md` — Mermaid 图源文件，由正文页引用。

## 刻意不覆盖

以下主题**不属于** Repo Wiki，即使代码库中存在相关内容也不单独成章：

- 安装步骤、部署教程
- CI/CD 流水线说明
- 功能需求规格（属于 PRD）
- 领域术语定义（属于 `CONTEXT.md`）
- 架构决策理由（属于 `docs/adr/`）
- 品牌视觉规格（属于 `docs/design/DESIGN.md`）

## 模块页拆分原则

1. 按**代码目录 / package** 自然边界拆分，而非逐文件
2. 模块页标题优先使用 `CONTEXT.md` 中的领域词汇；若无对应术语，用代码中的 package / 目录名，并在页内注明「待纳入 CONTEXT」
3. 每个模块页至少 2 个源码锚点（职责定义处 + 主要对外接口处）
4. 模块总览页 `index.md` 须链接到所有子页

## 目录生成流程

1. 扫描代码库，识别入口文件与顶层 package / 目录结构
2. 按上表生成目录树草稿
3. 向用户确认（若用户未要求跳过确认）：模块拆分是否合理
4. 目录确定后逐页生成；目录就绪即可开始阅读已完成的页

## 语言

生成前确认语言（zh-CN 或 en）。**同一仓库只保留一种语言版本**——换语言重新生成会覆盖原有 Wiki 全部页面。
