# Repo Wiki 扫描规则

`/repo-wiki` 扫描代码库时必须遵循此规则。扫描范围**独立于**其他 skill 的文件读取，且始终受下列约束。

## 扫描方式

- **不拿预置文件清单** — 按目录逐层展开、按需读取
- 优先读取：入口文件、顶层 package / 目录、`README`（若存在且简短）
- 深入读取：与当前生成页相关的模块源码
- 约束上下文：若 `CONTEXT.md` 存在，读取以统一命名；若 `docs/adr/` 存在，读取以标注一致性

## 不进入扫描上下文

以下内容**不得**读入用于生成 Wiki 的模型上下文：

### 目录与产物

- 版本控制内部目录（如 `.git/`）
- 依赖目录（如 `node_modules/`、`vendor/`、`.venv/`）
- 构建产物（如 `dist/`、`build/`、`target/`、`__pycache__/`）
- 缓存与本地运行状态（如 `.cache/`、`.next/`、`*.log`）

### 忽略规则

- 根目录 ignore 规则（如 `.gitignore`）所排除的内容

### 敏感文件

文件名（不含路径中间段）匹配以下敏感词的疑似密钥或配置文件：

- `token`、`secret`、`credential`、`password`

**例外**：正常业务源码不受影响（如 `tokenService.ts`、`PasswordValidator.java`）。

### 其他

- 符号链接指向的文件和目录
- 大二进制文件（图片、音视频、编译二进制）

## 读取但不复制全文

| 路径 | 处理方式 |
|------|----------|
| `CONTEXT.md` | 读取 — 用于统一 Wiki 术语命名 |
| `docs/adr/` | 读取 — 用于标注代码与 ADR 是否一致 |
| `docs/design/` | 可读 — 仅用于识别 UI 相关模块，**不复制**视觉规格 |
| `docs/prd/` | **不读取全文** — 防止 Wiki 成为第二 SSOT；最多读 PRD 文件名列表以了解功能域 |
| `docs/repo-wiki/` | 刷新时读取现有页与 `_meta.yaml` |
| `docs/agents/` | 读取 `wiki.md` 布局与维护说明 |

## 安全

- 不要在 Wiki 正文中写入密钥、token、密码、连接字符串
- 若源码中含敏感默认值，Wiki 只描述「配置项存在」并指向配置边界页，不复制具体值

## 代码变更检测（刷新时）

刷新 Wiki 前：

1. 读取 `docs/repo-wiki/_meta.yaml` 中的 `commit`
2. 获取当前 HEAD commit
3. 若相同且无用户强制整库重生请求 → 告知用户 Wiki 已是最新，询问是否仍要刷新
4. 若不同 → 执行增量或整库重生（由用户选择或按变更规模自动建议）

## 并发

同一仓库同时只跑一个 Wiki 生成任务。若用户请求新生成而任务已在进行，等待或询问是否停止当前任务。
