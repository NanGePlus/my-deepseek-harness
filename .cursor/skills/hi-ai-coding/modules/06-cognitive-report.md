# ⑥ 认知报告（小白详细版）

## 交互纪律

1. **先在聊天中完整预览**报告（允许分段预览：先发「封面+纪要」，再发「认知陈述+附录」，但落盘前须凑成完整稿让用户确认）。
2. 问用户是否写入本地；**仅在明确同意后**写入。
3. 默认路径建议：`docs/agents/ai-coding-literacy-report.md`（用户可改路径；创建目录前先征得同意）。
4. **不要**在报告或收尾中写「建议下一步去读某指南 / 去用某 Skill」等推荐。
5. 续讲时若文件已存在：征得同意后读取，更新对应章节，保留未改部分。

## 中断（今天先到这）

预览并可选落盘**阶段性详细报告**：

- 「课程纪要」里**已学章节必须写细**（标准同结业，不可缩成三五行）
- 「未覆盖章节」列出剩余，并写「尚未学习，结业后补全」
- 「我的认知陈述」能写的章节先写细；写不了的标「待结业补全」
- 「术语小词典」「最小交付链」等附录：已涉及的词先收入，未讲的标待补

## 结业（主线走完或用户要求先结业）

预览并可选落盘**完整详细报告**。对零基础小白：**宁可偏长、不可偏略**——报告应能单独拿出来复习，即使不再打开对话也能看懂本课讲过的东西。

---

## 生成质量要求（必须遵守）

1. **面向小白**：每个要点尽量用「是什么 + 为什么重要 + 一个生活/开发中的小例子」；避免只有黑话列表。
2. **宁详勿简**：结业完整报告建议体量大约 **2500～5000 字（中文）** 量级；阶段性报告按已学比例酌减，但已学章不得敷衍。
3. **禁止偷懒写法**：不要只写 3～6 条短 bullet 就完事；每章纪要至少包含下面模板要求的小节。
4. **忠实于本课**：根据**实际讲过**与用户插问写；未讲章节写「未覆盖」。可复述 modules 中的教学要点，但要改写成「给自己看的复习稿」，不要整段机械粘贴。
5. **认知陈述要展开**：每个问题写成 **一小段话（建议 80～200 字）**，不是一行口号；优先用用户原话，不足处助手代拟并标「（待你确认）」。
6. **保留课堂痕迹**：重要插问、用户举过的例子、纠正过的误解，写入「过程与讨论」专节。

## 助手生成时的操作顺序

1. 回顾本会话已讲章节、插问、用户基础与是否听了短剧本。
2. 按模板**从「总述」写到「附录」**，缺信息处写「（本课未覆盖）」或「（待你确认）」，不要留空白标题。
3. 聊天预览时可用大标题分段发送，但明确「以下为完整报告预览」。
4. 用户同意落盘后，写入**完整 Markdown**（不要只写纪要缩略版）。
5. 若用户嫌长：可提供「目录 + 锚点」，但仍须保留详细正文；**不得擅自改回短版**，除非用户明确要求「改成简版」。
