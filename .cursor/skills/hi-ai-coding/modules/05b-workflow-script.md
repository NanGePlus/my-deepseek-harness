# ⑤′ 短剧本（可选）— 口述走一遍主链路

> 虚构需求，**只讲故事，不改代码**。帮助把第⑤章地图串起来。

## 场景

小白想给「待办应用」加：**完成任务时加 10 积分**。

## 口述流程

1. **P1 对齐**
   用拷问澄清：积分存在哪？谁能加？签到是否另算？失败怎么办？
   - 若只想谈清楚：`/grill-me`
   - 若要留下术语/决策：`/grill-with-docs` → 可能写入 `CONTEXT.md` 等

2. **P2 规划**
   `/to-prd`：写成可验收的 PRD（含如何测「积分 +10」）。
   `/to-issues`：拆成一个（或少数）垂直切片 Issue，而不是「先写完全部测试再写代码」。

3. **P3 实现**
   `/triage`：Issue 变到可给 Agent 做。
   拉分支 → `/tdd`：先定失败的验收信号，再实现，再重构。
   开 PR → CI 绿灯 → 审查 → 合并。

4. **若中途坏了**
   `/diagnose`：先建立可重复的失败信号，再修。

5. **和 Vibe 的差别（回扣）**
   每步都有可检查物：共识/PRD/Issue/测试/PR；不是聊天里连喊十次「再改改」。

## 练习（轻量核对）

**题**：这个剧本里，为什么不建议一上来就对 AI 说「把积分做完」然后连续改？

**推荐答案**：范围和验收还没对齐，AI 只能猜；后面也没有 Issue/测试/PR 这些检查点，出了问题很难回放。

对用户：题目 + 推荐答案一起给，问是否认同即可。
