# ② AI Coding vs Vibe Coding，以及为何要可控

## Vibe Coding 是什么

凭感觉连续让 AI「再改改」，自己缺少清晰范围与验收，也不求理解关键改动，直到界面「看起来差不多」。

特征：过程难复查、结果难解释、债务难控制。

## 对照

| | 更可控的 AI Coding | Vibe Coding |
|--|-------------------|-------------|
| 目标 | 说清要什么、不要什么 | 含糊「优化一下」「做好看点」 |
| 过程 | 小步改 + 看 diff + 跑一跑 | 大包接受、连环「再试试」 |
| 对 AI | 当会胡说的初级同事 | 当全知魔法箱 |
| 结果 | 可复查、可回退、可讲清 | 偶然能成，规模一大易崩 |

## 为何要更可控（而不是随意而为）

1. **AI 会自信地错**：编造 API、改超范围、漏边界条件很常见。
2. **软件会累积**：今天「差不多」的债，明天变成不敢动的泥球。
3. **协作需要共同语言**：Git、PR、CI、Issue 都假设「改动可描述、可检查」。
4. **责任在人**：上线出问题，不能只怪模型。

可控 ≠ 慢。可控是：**同样用 AI，但每步留得下检查点**（范围、diff、运行、回退）。

## 练习（轻量核对）

**题**：vibe coding 和「让 AI 帮忙写代码」差在哪？

**推荐答案**：差不在用不用 AI，而在有没有定范围、做验收、搞懂关键改动。一直凭感觉「再改改」就是 vibe；有检查地协作就不是。

对用户：题目 + 推荐答案一起给，问是否认同即可。
