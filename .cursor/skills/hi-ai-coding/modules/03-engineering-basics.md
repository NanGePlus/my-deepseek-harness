# ③ 开工前工程常识

> 深度：概念 + 为什么需要 + 最小词汇；可选认门（指出大概看哪）。**不教**命令跟做，不挡认知毕业。
> 「几乎零基础」建议整章听；「有经验」可对 §1 说跳过。

## 1. 认世界（可跳）

| 词 | 是什么 | 为何要知道 |
|----|--------|------------|
| **项目文件夹 / 仓库** | 你的代码与配置所在的目录 | AI 改的是这里面的文件 |
| **IDE**（如 Cursor） | 写代码、看文件、对话 AI 的应用 | AI Coding 主要发生在这里 |
| **终端** | 用文字下命令的窗口 | 安装、启动、测试、Git 常在这里跑 |

可选认门：在自己电脑上指一下「项目根目录」「终端面板」在哪（找不到可跳过）。

## 2. Git：本地改动的时光机

**解决什么问题**：代码改乱了能否回到昨天？多人改同一项目如何不互相覆盖？

**最小词汇**：

| 词 | 含义 |
|----|------|
| commit（提交） | 给当前改动拍一张可回退的快照并写说明 |
| branch（分支） | 一条平行的修改线，常用来做功能/修 bug |
| remote（远程） | 放在 GitHub 等上面的副本 |

和 AI Coding：AI 改完文件后，你仍应用 Git 管住「什么时候定稿、如何回退」；也可让 AI **建议**提交说明，但**是否提交**由你决定。

## 3. GitHub（或同类平台）：代码的家与协作台

**解决什么问题**：代码放哪备份？别人怎么看到你的改动？讨论与审查在哪发生？

**最小词汇**：仓库（repo）、clone（下载到本地）、push（推到远程）、Pull Request / PR（请求把分支合并进去）。

## 4. PR 与 Code Review

| 词 | 解决什么 |
|----|----------|
| **PR** | 把「我这批改动」打包说明，请求合进主线 |
| **Code Review** | 人或机器人检查改动是否合理、安全、符合约定 |

和 AI Coding：AI 可以起草 PR 说明；**审查与合并决策**仍在人（或团队规则）。

## 5. CI（持续集成）

**解决什么问题**：每次改动后，自动跑测试/检查，尽早发现「我以为好了其实坏了」。

**最小词汇**：pipeline / 工作流、绿灯（通过）、红灯（失败）。

认门（可选）：在 GitHub 仓库的 Actions（或同类）里看一次最近是绿还是红——只看，不要求会配。

## 6. Issue / 任务单

**解决什么问题**：需求、bug、想法放哪跟进，避免只活在聊天记录里。

和本仓库工作法：Issue 跟踪器是流程中枢（后面第⑤章会接上）。

## 7. 串成一条最小交付链（认知）

```
在 IDE 里改代码（可与 AI 协作）
  → 看懂改了什么（diff）
  → commit（本地定稿）
  → push / 开 PR（分享与审查）
  → CI 检查
  → 合并进主线
```

## 练习（轻量核对）

**题**：Git、GitHub、CI 各主要解决哪一类问题？（各用半句）

**推荐答案**：Git——管本地历史与分支；GitHub——远程存放与协作（含 PR）；CI——每次改动自动检查是否搞坏东西。

对用户：题目 + 推荐答案一起给，问是否认同即可。
