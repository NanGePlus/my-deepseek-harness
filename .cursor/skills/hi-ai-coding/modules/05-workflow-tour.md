# ⑤ 本仓库 AI Coding 工作法全流程导览

> 深度：阶段地图 + 每个核心 Skill「何时用 / 产出什么」。不教逐步操作。
> 细节与跟做见仓库内保姆级指南与各 Skill 原文（本课结业**不主动推荐**去读哪一份）。

## 核心思想（一句话）

把 AI 编程拆成**可组合的小步骤**，每步都有**可检查产物**；用 **Issue 跟踪器** 做中枢；用**垂直切片**一次打通一小条用户价值（而不是先写完全部测试再实现）。

目标：**真工程**，不是 Vibe Coding。

## 阶段地图（总览）

| 阶段 | 在干什么 | 典型产物 |
|------|----------|----------|
| **P0 工程基建** | 每仓一次：接好跟踪器、标签、领域文档布局 | `docs/agents/*`、`AGENTS.md` / `CLAUDE.md` |
| **P1 需求对齐** | 把想法拷问清楚，必要时写下领域/架构/设计约定 | 对话共识；或 `CONTEXT.md` / ADR / `DESIGN.md` |
| **P2 规划与拆解** | 写成 PRD，再拆成可领取的垂直切片 Issue | PRD、功能/UI/Design Issues |
| **P3 分拣与实现** | 分拣 → 简报 → 分支 → TDD 实现 → PR + CI | 代码、测试、PR |
| **P4 横切能力** | 随时：排错、看懂结构、架构维护 | 诊断结论、架构图/报告 |

```text
P0 基建 → P1 对齐 → P2 规划 → P3 实现（循环多个 Issue）
                ↘ 随时可用：diagnose / zoom-out / improve-architecture
```

## 核心 Skill 索引（何时用 / 产物）

| Skill | 何时用 | 产出什么 |
|-------|--------|----------|
| `/setup-skills` | 新仓库要上这套工作法 | Issue 跟踪器配置说明、标签、领域文档布局 |
| `/grill-me` | 想法还糊，先压力测试；先不写文档 | 对话中的共识 |
| `/grill-with-docs` | 要对齐并沉淀长期文档（含 UI 模式等） | `CONTEXT.md` / ADR / `DESIGN.md` |
| `/to-prd` | 共识够了，写成可执行的需求规格 | 本地 `docs/prd` 确认 → PRD Issue |
| `/to-issues` | PRD 已有，拆成可独立实现的切片 | 垂直切片 Issues（功能 / UI / Design） |
| `/triage` | Issue 要分拣、补信息、准备给 Agent | 状态变更、Agent 简报 |
| `/tdd` | 规范够了，红→绿→重构实现 | 代码 + 测试 + PR |
| `/diagnose` | 疑难 bug / 性能回归 | 反馈回路与回归验证 |
| `/zoom-out` | 看不懂模块关系 | 架构/调用关系（对话中） |
| `/improve-codebase-architecture` | 要加深模块、治理结构 | 架构改进报告等 |

## 四类痛点 ↔ 思路（认知）

| 痛点 | 思路方向 |
|------|----------|
| AI 没听懂 | 先对齐（grill），再写代码 |
| 对话太啰嗦 | 共享术语表；Issue 用绑定指向 PRD，不复制全文 |
| 跑不通 | 测试与诊断闭环 |
| 越改越乱 | 规划切片 + 拉高视角看架构 |

## 两条纪律（点到为止）

1. **垂直切片**：一条可演示的用户路径做通，再做下一条；不要水平「先写完全部测试再实现」。
2. **有 UI 时要有设计治理**：品牌与页面规格有明确存放处（工作法里用 `DESIGN.md` / PRD 页面清单等）——细节跟做时再学。

## 练习（轻量核对）

**题**：P1 和 P3 最大的差别是什么？

**推荐答案**：P1 解决「要做什么、对齐没有」（需求/文档）；P3 解决「按规范实现并合并」（分拣、编码、PR/CI）。

对用户：题目 + 推荐答案一起给，问是否认同即可。
