# ④ 如何更好的 AI Coding

## 1. 角色分工

把 AI 当成**进度很快、但会自信胡说的初级同事**：

| 你 | AI |
|----|-----|
| 定目标、范围、验收 | 提方案、写草稿、改文件 |
| 提供上下文与反例 | 在上下文内执行 |
| 审查 diff、运行、说不对在哪 | 按反馈迭代 |

## 2. 好委托（Brief）的最小零件

尽量有：**目标、范围、约束、验收、上下文（含「不要做成…」）**。
不必每次写长文；缺得越多，AI 越脑补。

| 坏 | 更好 |
|----|------|
| 「优化登录」 | 「失败时用现有 Toast 显示后端 msg；别改成功跳转；用账号 A 错密码应看到文案 X」 |
| 「给用户加积分」 | 「签到成功 +10 到 user.points；只改签到路径；测试号签到后积分 N→N+10」 |

## 3. 验收闭环

AI 说「好了」≠ 真好了。最少：

1. 看 diff（有没有改超范围）
2. 按约定跑一次 / 点一次
3. 不懂的行让 AI 解释再决定接受

## 4. 反模式（短表）

| 模式 | 对策 |
|------|------|
| 范围雪球 | 写明「只许动…」 |
| 幻觉 API | 让它指出依据文件；你打开核对 |
| 长对话挖坑 | 重要约束写进规则/项目说明；或开新对话并先贴约束 |
| 整包盲接受 | 拆小步；先看变更列表 |

## 5. 工具最小集（Cursor / Claude Code / Codex）

| 中性能力 | Cursor | Claude Code | Codex |
|----------|--------|-------------|-------|
| 问答对话 | Chat | 会话对话 | 对话线程 |
| 改多文件的 Agent | Agent | agentic 工作流 | agent 任务 |
| 项目持久约定 | Rules / `AGENTS.md` 等 | `CLAUDE.md` 等 | 项目指令 / `AGENTS.md` |
| 流程剧本 | Skills | Skills / 自定义指令 | 自定义指令 / skills |
| 塞上下文 | `@文件` | 路径 / 自探 | 附加文件 / 仓库上下文 |

**关键旁注**：规则文件名因产品而异；Skill 不一定自动触发；Agent 跑命令常要批准——别一键全开到失控。重要约定写进规则/项目说明，别只活在聊天里。

可选认门：找到「普通聊天」「Agent」「项目规则」入口（找不到可跳过）。

## 练习（轻量核对）

**题**：AI 说功能做好了，你最少做哪两件事？

**推荐答案**：① 看改了哪些文件（有无超范围）；② 按说好的标准实际跑/点一次。

对用户：题目 + 推荐答案一起给，问是否认同即可。
