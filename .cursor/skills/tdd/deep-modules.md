# 深层模块

源自《A Philosophy of Software Design》：

**深层模块** = 小接口 + 大量实现

```
┌─────────────────────┐
│   小接口             │  ← 少方法、简单参数
├─────────────────────┤
│                     │
│                     │
│ 深层实现             │   ← 复杂逻辑隐藏在内
│                     │
│                     │
└─────────────────────┘
```

**浅层模块** = 大接口 + 少量实现（应避免）

```
┌─────────────────────────────────┐
│  大接口                          │  ← 多方法、复杂参数
├─────────────────────────────────┤
│  薄实现                          │  ← 仅透传
└─────────────────────────────────┘
```

在设计接口时，问自己：

- 我能减少方法的数量吗？
- 我能简化参数吗？
- 我能把更多复杂性隐藏在内部吗？
